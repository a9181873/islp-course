# 內容契約

## 來源優先順序

1. 課程事實與檔名：`https://github.com/a9181873/islp-course`。
2. 正式可達網址與重新導向：`https://learn.dky.tw/`。
3. Agent 工具與論文摘要：官方儲存庫、論文原始頁與專案內 `content-sources.md`。
4. 介面文案與學習順序：`client/src/data/learningCatalog.ts`。

來源衝突時不要猜。保留來源、差異與日期，先選擇能維持既有使用者網址與進度的方案。

## Lesson 必要欄位

- `id`：穩定、唯一，發布後不得任意更換。
- `number`：教材章節定位，不當成唯一鍵。
- `title`：繁體中文、可掃讀、忠於課程主題。
- `summary`：回答本課解決的問題，不複製章節全文。
- `href`：正式可達的 canonical 或相容網址。
- `minutes`：合理的單次專注時間，用來協助開始，不是假精確工時。
- `kind`：`觀念`、`實作` 或 `案例`。
- `tags`：少量、可搜尋，避免同義詞無限膨脹。

## 章節學習品質

每章必須交代：

1. 學習者位於哪一章、哪一週。
2. 完成後能做出的可觀察行為。
3. 至少一個應用、比較或實作節點。
4. 課程時間、內容類型與下一步。
5. 可透過目錄與全站搜尋抵達。

## 上游同步對應表

同步前整理：

| 上游變更 | catalog 動作 | 相容性檢查 |
| --- | --- | --- |
| 新增 HTML | 新增 lesson 或 resource | 章節位置、標題、網址、kind |
| 改名／移動 | 更新 href，必要時做 redirect | 舊網址、lesson id、搜尋 |
| 刪除 | 先確認替代頁再移除 | 外部引用、既有進度、404 |
| 內容更新 | 視差異更新 summary／tags | 不搬運受版權保護全文 |
| 新研究文章 | 加入 resource | 第一手來源、日期與實作價值 |

不要用檔案數量直接推導課程數量；同一教材可能有 root 與 `statistics/` 的歷史副本。
